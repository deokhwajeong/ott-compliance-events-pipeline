      How these numbers were produced

      1. demo/export_fixture.py generates synthetic subscribers, devices and titles with the same generator as src/scripts/seed_demo.py (IP addresses from RFC 5737 documentation ranges).
      2. Each event is posted to the real FastAPI app (POST /events), then processed with POST /process/drain: per-market regulation rules, consent and identifier checks, behavioral signals and the IsolationForest + LOF anomaly score.
      3. Data subject requests travel in the same stream as dsr_access_request, dsr_deletion_request, dsr_extension and dsr_completed events. The pipeline keeps one record per request, flags late completions (for example gdpr_data_deletion_violation), and GET /api/v1/dsr reports each request's deadline as of the export time. Open requests within 7 days of the deadline are shown as at risk.
      4. The results are written to data/fixture.json; this page only reads and filters that file. Rules are a model for engineering discussion, not legal advice.
